## 用語集 — 傷と概念の対応

概念は傷の圧縮である。この表は、どの傷がどの概念を生んだかを引くためのもの。

| 概念 | 生んだ傷 | 部 |
|---|---|---|
| 情報隠蔽 | 格納形式を1つ変えると全モジュールが変わる | プロローグ |
| 正規化 | 同じ事実を2箇所に書いて食い違う | プロローグ |
| GC | free を忘れる、2回呼ぶ | 第1部 |
| ACID | 途中で落ちてデータが半分だけ書かれる | 第1部 |
| 8つの誤謬、分散オブジェクト第一法則 | ループの中のリモート getter、部分故障 | 第1部 |
| SOA の4テネット | 実装の型を共有して相手の内部に結合する | 第1部 |
| 賢いエンドポイントと土管のパイプ | ESB チームが全社のボトルネックになる | 第1部、第3部 |
| Convention over Configuration | クラスを1つ足すのに XML を3ファイル直す | 第1部、第2部 |
| UML はスケッチとして | 締切の夜に図だけが古くなる(MDA) | 第1部 |
| Data Mapper | ドメインと DB と表示が1クラスに同居する(神クラス) | 第2部 |
| オンラインスキーマ変更 | ALTER TABLE が数時間テーブルをロックする | 第2部、第4部 |
| スキーマの復権 | スキーマがアプリコードに暗黙のまま散乱する | 第3部 |
| 境界づけられたコンテキスト | 「顧客」の意味が部署ごとに違うのに1つにする | 第3部 |
| Saga、冪等キー、outbox | 境界を跨ぐトランザクションが無い、メッセージが重複する | 第3部 |
| アーキテクチャ量子 | 分けたつもりで同時デプロイが要る(分散モノリス) | 第3部、第4部 |
| blameless postmortem | 責められるので情報が隠され、同じ事故が繰り返す | 第3部 |
| 漸進的型付け | 全部を一度に型付けできないで移住できない | 第4部 |
| 適応度関数 | 文書に書いた境界がレビューをすり抜ける | 第4部 |
| デプロイとリリースの分離 | レバーが1本しかなく、戻すと全部戻る | 第4部 |
| エラーバジェット | 信頼性と速度の口論が毎回起きる | 第4部 |
| Four Keys | 「変更を減らせば安全」を誰も反証できなかった | 第4部 |
| 逆コンウェイ戦略 | 組織図の形がそのままシステムになる | 第4部 |
| スキーマ駆動生成 | ドキュメントと実装、SQL と型がズレる | 第5部 |
| expand/contract | 新旧バイナリが同じ DB を触る間に壊れる | 第5部 |
| 3軸の分離 | 可逆な軸を先に動かし、不可逆な軸を放置する | 第5部 |
| ゴールデンパス | 文化は説得だが、説得は続かない | 第5部 |
| SPACE | 単一指標がゲーム化して腐る | 第5部 |
